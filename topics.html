SQL Injection Prevention

SQL Injection is a critical vulnerability where attackers manipulate database queries using malicious input. This can allow unauthorized access to sensitive data or even complete control over the database

❌ Vulnerable Code


query = "SELECT * FROM users WHERE username = '" + username + "'"
cursor.execute(query)

This code directly inserts user input into the query, making it vulnerable to attacks | it's dangerous ?

✅ Secure Code


query = "SELECT * FROM users WHERE username = %s"
cursor.execute(query, (username,))

Using parameterized queries prevents attackers from injecting malicious SQL

Cross-Site Scripting (XSS) Defense

XSS attacks happen when malicious scripts are injected into web pages. These scripts can steal user data, session cookies or modify page content

❌ Vulnerable Code


return f"
{user_input}
"

User input is directly rendered without sanitization

✅ Secure Code


import html
safe_input = html.escape(user_input)
return f"
{safe_input}
"

Escaping input prevents script injection

Input Validation & Sanitization

Input validation process only safe and expected data while sanitization filter and clean input to make it safe. This prevents many attacks such as injection, crashes, or unexpected behavior

❌ Vulnerable Code


age = int(user_input)

if invalid input is it has a potential to exploit valuble data

you are cooked

✅ Secure Code


if user_input.isdigit():
    age = int(user_input)
else:
    print("Invalid input")

Using this step to validat the input can help to keep your valuble data and information safe

Secure Password Hashing

Passwords must never be stored in plain text. Hashing converts passwords into secure values. Without required key no one can find it

Fact - using multiple encryptions your password will be more powerfull

❌ Vulnerable Code


password = "mypassword"
save_to_db(password)

Plain text passwords can be easily stolen

✅ Secure Code


import bcrypt
hashed = bcrypt.hashpw(password.encode(), bcrypt.gensalt())
save_to_db(hashed)

Hashing protects passwords even if the database is compromised

HTTPS & Secure Communication

HTTPS ensures that data transmitted between users and servers is encrypted. Without HTTPS, attackers can intercept sensitive data such as passwords

❌ Vulnerable Code


import requests
requests.get("http://example.com")

Data is sent without encryption, making it vulnerable to interception | most of the browsers even reject to redirect these sites

✅ Secure Code


import requests
requests.get("https://example.com")

HTTPS encrypts communication and protects sensitive data

https port: 443

Principle of Least Privilege

This principle ensures that users and systems only have the minimum permissions required to perform their tasks, reducing security risks

❌ Vulnerable Code


db_user = "admin"

Admin access only available to the specified people

✅ Secure Code


db_user = "readonly_user"

Limiting permissions for users help to prevent attackers exposing vulnerabilities without even trying

Secure File Uploads

File uploads can be dangerous if attackers upload malicious files. Proper validation ensures only safe files are accepted

❌ Vulnerable Code


file.save("uploads/" + file.filename)

File names are not validated and may contain malicious content

✅ Secure Code


import os

filename = os.path.basename(file.filename)

if filename.endswith(".jpg") or filename.endswith(".png"):
    file.save("uploads/" + filename)

Validating file types and names prevents malicious uploads

Error Handling & Logging Best Practices

Proper error handling ensures that sensitive system details are not exposed to users while still logging errors for developers.

❌ Vulnerable Code


print(error)

User only see an "error" messeage help to prevent exposing vulnerabilities

✅ Secure Code


import logging

logging.error("An error occurred")

giving full log of the error to find out what cause the problem
